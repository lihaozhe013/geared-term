# 直接 Web 页面支持需求规格

> 文档类型：产品需求，仅描述“需要什么”  
> 不包含：技术架构、Electron 注入方案、DOM selector、IPC 设计或实现排期  
> 状态：初稿  
> 更新时间：2026-09-19

## 1. 背景

产品当前通过 AI API 的 HTTP
streaming 展示回答，并能把 Shell 代码块拆成独立命令，为每条命令提供 Copy、Insert 和 Run。

新能力希望直接使用主流 LLM 的真实 Web 页面，复用用户已有登录态、订阅、模型选择、Web
search、附件和会话历史；同时把页面回答中的简单 Shell 代码块转换成与现有产品一致的终端操作体验。

该能力定位为“终端旁的 Web 问答与人工确认式命令桥”，不是让网页或 AI 自治控制终端。

## 2. 产品目标

1. 用户可在应用内使用主流 LLM Web 页面完成正常问答。
2. 页面中的 Shell 代码块可被识别并拆分为独立可操作命令。
3. 每条命令提供 Copy、Insert 和 Run，其中 Insert 是默认主操作。
4. 用户可以把当前终端可见上下文或 selection 方便地用于 Web 问答。
5. 网页只能提出命令候选，不能绕过用户动作直接操作终端。
6. 网站小规模改版时，故障应局限于对应网站支持，不影响终端核心。

## 3. 用户画像与主要场景

目标用户是需要在本地或远程终端中开发、安装软件、修复环境和排障的技术用户。

典型场景：

- 服务器缺少依赖，用户把报错交给 Web LLM，获得安装命令并逐条 Insert；
- CUDA、驱动、systemd、网络或权限问题需要边看终端边咨询；
- 用户不愿给自治 agent 完整 shell 权限，但愿意逐条审核建议命令；
- 敏感环境中只允许 AI 看用户明确提供的有限屏幕内容；
- 回答包含多条带注释的 Bash/PowerShell 命令，用户选择性执行；
- 用户依赖 Web LLM 已有的搜索、附件、历史或付费模型能力，不希望重新配置 API。

## 4. 范围

### 4.1 首期范围

- 在应用内打开受支持的主流 LLM Web 页面；
- 保持该网站正常登录和问答能力；
- 支持简单、常规的 Markdown 风格代码块；
- 识别明确标注为 Shell 的代码块；
- 解析 Bash-family 与 PowerShell 类命令；
- 将注释与命令分开展示；
- 将一个代码块拆成多个可独立操作的 top-level command；
- 提供 Copy、Insert、Run；
- 支持 LLM 回答 streaming 期间的持续更新；
- 支持把 terminal selection 或有限 buffer 上下文交给用户，用于粘贴/发送到网页问答；
- 对网站不支持、识别失败或解析低置信度提供清晰降级。

### 4.2 首期不要求

- 支持所有网站或任意网页；
- 绕过网站登录、验证码、地区限制、反自动化或服务条款限制；
- 处理 canvas 渲染、复杂 Shadow DOM、强虚拟化或非文本代码展示；
- 自动理解所有未标语言的代码块；
- 允许网页自动执行命令；
- 提供自治 agent loop；
- 从网页抓取并建立永久知识库；
- 保证网站改版后零维护；
- 替代原有 API 模式，二者可并存。

## 5. 支持对象

### 5.1 网站支持级别

每个网站具有独立状态：

- **支持**：核心流程已验证；
- **实验性**：可用但可能因页面变化失效；
- **暂不支持**：仅作为普通网页使用，不提供命令增强；
- **失效**：原先支持，但当前版本检测到适配异常。

首期具体网站名单由实现开始时确定，但至少应覆盖用户实际使用的主流 LLM
Web 服务中的一到两个，之后逐站增加。

### 5.2 代码块语言

首期至少支持以下语言标签的规范化别名：

- Bash-family：`bash`、`sh`、`shell`、`zsh`；
- PowerShell：`powershell`、`pwsh`。

`fish`、Windows
CMD 或其他 shell 是否开放，由现有 parser 的可靠程度决定。未明确识别的语言不得默认显示 Run。

## 6. Web 页面基础体验需求

### WEB-001 页面访问

用户能够打开受支持 LLM 的正常 Web 页面，并使用站点本身提供的登录、会话、模型、搜索和附件功能。

### WEB-002 登录态

用户完成登录后，在符合站点自身规则的前提下，登录态应在应用重启后保持。产品不得记录用户密码。

### WEB-003 导航

用户能够执行正常的站内导航、前进、后退、刷新和打开会话。外部跳转必须有可理解的目标提示。

### WEB-004 原站可用性

命令增强不得阻断文本输入、选择、复制、滚动、代码块原始复制按钮、附件和正常问答。

### WEB-005 支持状态

当页面增强未启用、已失效或只支持普通浏览时，用户能够看见非打扰式状态说明，不应误以为命令按钮仍可靠工作。

## 7. 代码块发现与识别需求

### CMD-001 发现代码块

系统应发现回答中已渲染的普通代码块，包括回答 streaming 过程中后续出现的代码块。

### CMD-002 仅处理 Shell

只有语言标签明确为已支持 Shell，或产品以足够高置信度判定为 Shell 时，才进入自动拆分流程。

### CMD-003 保留原文

无论增强是否成功，网页原始代码块必须继续可查看、选择和使用。增强 UI 不得成为代码内容的唯一副本。

### CMD-004 去重

同一个代码块被页面重复渲染或更新时，不得产生重复的命令组、重复按钮或重复操作。

### CMD-005 streaming 更新

回答生成过程中，代码块内容发生变化时，命令候选应随之更新；旧候选不得在内容变化后继续以“已稳定”的状态存在。

### CMD-006 稳定状态

系统必须区分“仍在生成/变化”和“当前已稳定”。仍在变化的代码块不得提供直接 Run。

### CMD-007 失败降级

无法识别语言或无法可靠拆分时，应保留原代码块，并可选择提供整块 Copy/Insert；不得伪装成精确拆分结果。

## 8. Shell 命令解析需求

### PARSE-001 拆分单位

命令拆分单位是可独立提交的 top-level shell statement，不是物理行。

### PARSE-002 注释处理

纯注释不作为可执行命令。与后续命令相关的前导注释应作为说明保留并显示在该命令附近。

### PARSE-003 多行命令

下列结构不得按换行错误拆开：

- 反斜杠或 PowerShell backtick 续行；
- pipeline；
- `&&` / `||` 链；
- heredoc；
- 引号中的换行；
- subshell 与 command substitution；
- `if`、`for`、`while`、function 等复合结构；
- 多行环境变量前缀。

### PARSE-004 Shell 差异

Bash-family 与 PowerShell 的语法和续行规则必须分别处理，不得用同一套简单换行规则混用。

### PARSE-005 保真

Insert、Run 和 Copy 使用的命令文本必须保留执行语义所需的换行、缩进、引号、转义和 heredoc 边界。

### PARSE-006 低置信度

当拆分结果可能改变执行语义时，系统必须降级为整块候选，或只保留 Copy，不得输出看似独立但语义不完整的命令。

## 9. 命令展示需求

### UI-001 独立命令行

每个解析后的命令以独立 command row/card 呈现，显示：

- 关联注释或用途说明；
- 完整命令文本；
- multiline 状态；
- Copy、Insert、Run 可用状态。

### UI-002 与原代码块关联

增强 UI 必须在视觉上明确属于哪一个原始代码块，页面滚动或 streaming 更新后不应错位到其他回答。

### UI-003 长命令

长命令和多行命令应可完整查看，不因截断导致用户在审核时遗漏危险参数。

### UI-004 状态反馈

Copy、Insert、Run 后提供明确且短暂的成功/失败反馈；失败不能静默。

### UI-005 不抢焦点

代码块更新和增强 UI 刷新不得抢走网页输入框或终端的当前焦点。

## 10. Copy、Insert 与 Run

### ACT-001 Copy

Copy 将单条命令的精确文本写入剪贴板，不包含展示性注释、按钮文字或网页其他文本，除非用户选择“复制整个代码块”。

### ACT-002 Insert

Insert 将命令写入当前明确选中的 terminal session，但不发送 Enter/Return，不自动执行。

### ACT-003 Insert 默认优先

Insert 是默认主操作；Run 的视觉优先级不得高于 Insert。

### ACT-004 Run

Run 只有在用户明确点击后，才把命令写入当前 terminal session 并提交执行。

### ACT-005 目标可见

执行 Insert 或 Run 前，用户能够确认目标 terminal
session。若当前没有有效目标，操作必须禁用并说明原因。

### ACT-006 防止错发

用户点击后若目标 session 已关闭、切换或失效，系统不得静默把命令发往另一个 session。

### ACT-007 重复点击

连续点击 Run 不得在用户无明确意图时导致同一命令被意外重复提交。

### ACT-008 streaming 禁止 Run

代码块仍在生成、变化或尚未达到稳定条件时，Run 必须不可用；Copy 和 Insert 可根据完整度决定是否开放，并清楚标记内容可能继续变化。

### ACT-009 高风险命令

对于明显具有破坏性的命令，产品应增加确认强度或只允许 Insert。风险提示是辅助审核，不构成安全保证。

### ACT-010 多行粘贴

Insert 或 Run 涉及多行命令时，必须遵循现有终端的多行粘贴安全策略，并让用户看清实际将发送的文本。

## 11. 终端上下文到 Web 问答

### CTX-001 上下文来源

用户可选择以下内容用于 Web 问答：

- 当前 terminal selection；
- 当前可见 viewport；
- viewport 加有限数量的上方 scrollback。

### CTX-002 用户主动

终端内容只有在用户明确触发时才被送往网页侧。默认不得后台持续同步完整终端输出。

### CTX-003 范围可理解

用户在发送前或发送时应能理解包含了 selection、viewport 还是额外历史，以及是否发生截断。

### CTX-004 默认最小化

默认优先 selection；无 selection 时使用有限 viewport 上下文。默认不包含完整 scrollback。

### CTX-005 alternate screen

vim、less、top、tmux 等 alternate-screen 场景必须以用户当前看到的屏幕为主要语义，不得误把历史 normal
buffer 当作当前状态。

### CTX-006 敏感信息

产品应提醒终端内容可能包含 token、路径、主机名或业务数据，并允许用户在发送前编辑或取消。

### CTX-007 交付方式

首期至少提供可靠的“复制为可粘贴内容”。若提供自动填入网页输入框，也必须保留用户发送前审核步骤，不自动提交问答。

## 12. 安全与信任边界需求

### SEC-001 网页不可信

所有远程网页内容均视为不可信，包括受支持的 LLM 网站及其生成内容。

### SEC-002 无直接终端权限

网页脚本、网页 DOM 和网页内生成内容不得直接写入 PTY、发送 Enter、读取任意终端历史、访问文件系统或启动进程。

### SEC-003 用户动作门槛

Insert 和 Run 必须由应用可信 UI 中的真实用户动作触发。网页只能提供待审核候选。

### SEC-004 最小数据暴露

网页不得按需拉取 terminal buffer。只有用户选定的上下文快照可进入网页问答流程。

### SEC-005 登录凭据

产品不得读取、导出或记录网站密码、session cookie、token 或其他认证材料用于无关目的。

### SEC-006 导航与新窗口

未知 scheme、下载、弹窗和跳转到非预期域时必须有受控行为，不得获得额外本地权限。

### SEC-007 内容注入影响

增强功能不得修改原回答文本的语义，不得伪装成网站原生安全提示，也不得遮蔽网站的重要警告。

### SEC-008 审计可见性

用户应能区分网页原始内容、应用生成的命令拆分 UI 和实际发往终端的动作。

## 13. 隐私需求

- 不默认采集或上传完整 terminal scrollback；
- 不把网页会话内容复制到应用遥测；
- 不在普通日志记录 terminal 文本、AI 回答全文、命令正文、cookie 或凭据；
- 如需崩溃诊断，默认只记录站点标识、功能状态和脱敏错误；
- 清除站点数据、退出登录和清除本地 Web 数据应有明确入口；
- 用户应能按网站禁用命令增强；
- API 模式与 Web 模式的数据边界应分别说明。

## 14. 可靠性与兼容性需求

### REL-001 局部失效

单个网站适配失效不得影响 terminal、API AI 模式或其他网站。

### REL-002 页面改版检测

当系统无法再可靠发现代码块或增强 UI 错位时，应倾向于关闭该站增强并报告“暂时不可用”，而不是继续提供可能对应错误内容的 Run。

### REL-003 性能

streaming 回答和长页面中的代码块增强不得造成明显输入延迟、滚动卡顿或 CPU 长时间占用。

### REL-004 大代码块

异常大的代码块应有解析上限和降级体验，不得冻结页面或应用。

### REL-005 页面重载

刷新、会话切换、历史消息重新渲染后，增强 UI 应能恢复且不重复。

### REL-006 错误隔离

解析器错误、网站结构变化或单个代码块异常必须被隔离，不能使整个 Web pane 崩溃。

## 15. 可访问性与键盘需求

- 所有 command action 可通过键盘访问；
- 焦点顺序稳定，不因 streaming 更新跳动；
- Copy、Insert、Run 有明确可访问名称；
- 禁用原因可被辅助技术读取；
- 不只用颜色区分“可执行、生成中、高风险、失败”；
- 支持用户缩放，不遮挡原代码块；
- 网页与 terminal 之间的焦点切换有一致快捷键，但不得劫持站点关键输入快捷键。

## 16. 可观测性需求

在不记录敏感正文的前提下，可记录：

- 网站支持状态；
- 发现的代码块数量与语言类型；
- 解析成功、降级或失败类别；
- Copy/Insert/Run 的匿名计数；
- 适配器异常类型；
- 版本和站点页面形态标识。

禁止记录：

- 命令正文；
- terminal buffer；
- AI 回答全文；
- 用户 prompt；
- cookie、token、password、private key。

## 17. 验收场景

### A. 基本 Bash 拆分

网页回答包含：

```bash
# Update package index
sudo apt update

# Install ffmpeg
sudo apt install -y ffmpeg

ffmpeg -version
```

验收：显示三条独立命令；两段注释分别归属正确命令；每条均有 Copy/Insert/Run；Insert 不执行。

### B. 多行命令

网页回答包含：

```bash
docker run \
  --rm \
  -v "$PWD:/work" \
  ubuntu:latest
```

验收：只生成一个命令候选，Copy/Insert 后文本保持语义。

### C. heredoc

网页回答包含 heredoc 写文件命令。

验收：从命令起始到终止 marker 为一个候选，不把 heredoc 内容作为多个命令。

### D. PowerShell pipeline

网页回答包含跨多行的 PowerShell pipeline 和 script block。

验收：按 PowerShell 规则保持完整，不按物理行拆分。

### E. streaming 中间态

模型先输出 `sudo apt remove`，随后补全参数。

验收：内容变化期间 Run 不可用；稳定后只对最终文本开放；旧文本按钮不残留。

### F. target session 切换

用户查看命令时切换活动 terminal。

验收：目标 terminal 清晰更新；如果点击瞬间目标状态不确定，操作失败而不是错发。

### G. 不支持的网站

用户打开普通文档网站或结构复杂的网站。

验收：网页正常使用；没有错误的命令增强；terminal 功能不受影响。

### H. 网站改版

已支持网站不再满足可靠识别条件。

验收：增强自动降级/禁用并提示；不出现错位 Run 按钮。

### I. 敏感上下文

terminal viewport 含疑似 token。

验收：发送由用户主动触发，用户可审核、编辑或取消；系统不在日志保留内容。

### J. 网页恶意脚本

网页脚本尝试触发命令操作或读取 terminal。

验收：不能获取 terminal 内容，不能 Insert，不能 Run。

## 18. 首期完成定义

首期 Web 页面支持可标记为完成，需同时满足：

1. 至少一个目标主流 LLM 网站的登录、问答和 streaming 回答可正常使用；
2. Bash-family 与 PowerShell 常规代码块可识别；
3. 旧项目现有 parser 的相关 fixtures 在 Web 来源下仍通过；
4. Copy、Insert、Run 与当前 terminal session 正确联动；
5. Insert 永不自动回车；
6. streaming 中间态不能 Run；
7. 网页无直接 terminal、文件系统或进程权限；
8. selection/viewport 上下文只在用户主动操作后进入网页流程；
9. 网站不支持或适配失效时有安全降级；
10. 终端/API AI 原有功能不因 Web 支持而回归。

## 19. 待产品决策

以下事项需要在实现前确定，但不影响本需求的核心边界：

1. 首期具体支持 ChatGPT、Claude、Gemini 中的哪一个或哪两个；
2. Web 登录数据是否按 workspace、profile 或全局隔离；
3. 是否保留 API AI 模式为并列入口，以及默认入口；
4. terminal context 是仅复制到剪贴板，还是允许自动填入但不发送；
5. 高风险命令的确认等级和用户可配置范围；
6. 是否支持 fish、CMD，以及何时开放；
7. Web pane 是否支持多标签页；
8. 网站适配失效时是否提供用户一键上报（仅含脱敏结构信息）。
